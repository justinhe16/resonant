# Brain plan (Phase 6a): a general agent loop on the local model

Status: **in progress** (2026-10-18): BR-1, BR-4, BR-5 and BR-7 built (§2, §6); `brain.mode` stays `intents` until the evals (BR-6, BR-8). Built with robot-surf in the waves of §5.

Texting Resonant should feel like texting Claude: general questions and conversation, looking around the Mini read-only, Resonant's own tools (still gated), extensions, other programs, Claude workers with Remote Control. Today every non-slash text is one intent label (`router/labeler.py`) → that intent's fixed toolset (`router/intents.py` `INTENT_TOOLS`) → `runners/local.py` capped at 3 model calls and 3 tool calls → a number guard that swaps the reply for a template. History is 5 earlier messages as user turns, nothing reads files or logs (`tools/builtin.py`), and nothing escalates (`escalate=True` is written and never read). "Where is mycelium?" had no route, so it failed.

The local qwen3-30B stays the brain. The harness changes, modeled on Claude Code's: one loop, an environment briefing, a memory index, general read tools, tools loaded on demand, a subagent for hard questions.

## 1. Owner decisions

- **Use cases:** questions about the Mini; personal assistant (calendar, email, reminders, notes); research and the web; named programs; photos, screenshots and voice; links; long-running asks ("watch X, tell me when Y"); other people with per-person grants (today's principals model). Group chats later.
- **Fast first, escalate:** the local loop answers; when it's stuck or the ask needs the web, email, calendar or an image, it hands it to a read-only Claude session and sends "looking into it…" first.
- **Email and calendar:** read and draft. Sending an email or creating, changing or answering an event asks first.
- **Programs:** each one a small extension with start, stop and status tools (e.g. trade-jev), not a generic runner.
- **Memory:** recent turns plus a small store of long-term facts.
- **Read scope:** `~/code`, `~/resonant`, Resonant's state, logs and docs, run transcripts. Never `~/Documents`, Mail, Messages, the Keychain, `~/.ssh`, `.env`-like files.
- **Ambiguity:** best guess for reads (say what it assumed), ask for writes.
- **Style:** a terse coworker.
- **Proactive:** yes, sparingly: a few notices a day, through the pulse.
- Everything that exists stays: fast path, gate, approvals, standing allows, kill switch, audit, extensions, MCP, workers and Remote Control, trust rules, pulse, dashboard.

## 2. Decisions

- **D1. One loop.** `runners/brain.py` handles every non-fast-path chat task. The fast path is unchanged (slash commands, `status`, `ping`, approval replies, the relay's `R4 …`, `/kill`). `brain.mode: intents | loop`, default `intents` until the evals pass (§4), then `loop` (BR-8). In loop mode the labeler is skipped (two prefixes would evict each other's KV cache with Ollama's one slot). A `ModelOutputError` in the loop falls back to the intents path for that turn.
- **D2. Prompt order for the cache.** Qwen's template puts the system text before the tool definitions in one turn, so anything that changes per turn goes after them: fixed system prompt (role, style, rules) → core tool schemas → the deferred-tool catalog (one line each; changes only on extension install) → facts index → rolling history (append-only, older part summarised) → one wrapped user turn with the **briefing** (time, repos and paths, runs with state and Remote Control links, extensions, open asks, health; from `dashboard/snapshot.py build_snapshot` local tier and `status.collect_status`; ≤1.5k tokens) and any "since we last talked" notes → the current message. A CI test pins the prefix hash.
- **D3. History as real turns.** The last ~10 exchanges as user/assistant turns (not `<prior_reply>` user turns), each capped; older ones folded into a running summary per principal. Tool results inside a task are still replayed as untrusted user turns.
- **D4. Tools: core plus deferred.** About 14 core tools always loaded: the read tools (D5), `remember`/`forget`, `ask_claude`, `load_tools`, notes and reminders add/list, `list_runs`, `run_activity`, `start_run`, `system_status`. Every other builtin, extension and MCP tool the principal may use is listed by name and one line; `load_tools(names)` adds up to 8 for the rest of the task. Per-principal filtering happens before anything is listed.
- **D5. Read tools** (`tools/files.py`, L0): `read_file`, `list_dir`, `search` (ripgrep), `tail_log`, `read_transcript`. Real path resolved, then the deny list, then the allowed roots (§1); symlinks out of a root and `..` refused; byte and line caps; output redacted (`redact.py`) and wrapped as untrusted data. Owner-only by default; members only through a grant.
- **D6. Taint.** A task that has read untrusted content (files, logs, transcripts, web, email, extension results, `ask_claude` output) is tainted; Resonant's own state reads and the facts index don't taint. A tainted task's model-chosen calls use a new origin `tainted`: the gate asks for L2 and L3 (standing allows don't apply, since they require `inferred`). The approval summary is code-built (`gate/summary.py`), so injected text can't reword what the owner approves. This is the one gate change in this plan.
- **D7. Limits.** At most 8 model rounds per task, reads free inside them; side effects ≤3 per task and one approval stops the task (both unchanged). Replies up to ~1500 chars. The hard number guard stays on the intents path only; in loop mode it logs and counts in the evals, and the prompt says to state only what it read. If the loop passes ~6 s, a short progress text goes out.
- **D8. `ask_claude`** runs as its own task (`runner="ask"`), not inside the chat step: "looking into it…" goes out, then the answer when it's back. `claude -p --restricted --tools Read,Grep,Glob,WebSearch,WebFetch --permission-mode dontAsk` with an **allowlist** of connector read (and draft, if the connector has one) tools, write tools never allowed (Gmail send, Calendar create, update, delete, respond), `Read` denied on the deny list, `--add-dir` for the read roots, no session persistence, `--max-turns 15`, 120 s timeout. The real connector tool names are read from the `init` event; it refuses to start when an expected read tool is missing. Concurrency 1 (`brain.ask_claude.concurrency`), a daily cap (~30), separate from worker slots; a usage limit backs off and tells the owner (`runners/claude.py` `usage_limit`). Sends and event changes come back as a code-built proposal and go through a gated tool. **Unverified:** whether `--restricted` keeps claude.ai connectors; BR-5 probes it first. Gmail and Drive need the owner to finish connecting them in claude.ai.
- **D9. Facts.** `~/.resonant/brain/facts/<slug>.md`, one fact each, with an index rendered into the prompt. `remember` and `forget` are L3 (do, then report), owner only.
- **D10. Media, links, watches, proactive.** Image and voice attachments from chat.db go to `ask_claude` (voice to local whisper when present). A link is summarised through `ask_claude` (WebFetch). "Watch X, tell me when Y" becomes a proposed job on an extension or a `watch` builtin, and asks first. Brain-authored notices go through the pulse with a daily cap on top of the hourly one.

### As built: BR-4 (context and memory)

`resonant/brain/` (context, briefing, history, facts), `store/brain.py` (migration 015) and `tools/facts.py`; contracts in [`interfaces.md`](interfaces.md#brain-context-and-memory-resonantbrain-br-4-migration-015). Not wired into a runner: BR-1 calls `build_context` per turn and `fold` after the reply.

- **D2.** `build_context` returns `BrainContext(prefix, history, turn)`. The prefix is the system message, then (only when non-empty) one user turn with the deferred-tool catalog and the facts index; a user turn rather than a second system message, so every chat template keeps it after the tools. The last turn is `<briefing>`, `<since_last>` notes, `Current time:` and the wrapped message. `tests/test_brain_context.py` pins `prefix_hash` and checks the prefix is byte-identical across turns and the briefing never lands before history. The briefing is about 1.5k tokens at most (6000 chars) with per-section caps and `+N more`; it lists approvals by summary, never their codes. A member's briefing is the status line only, with no facts and no notes.
- **D3.** Each exchange is a wrapped user turn and an assistant turn (500 and 800 chars). A fold runs once 15 exchanges are unfolded and keeps the newest 10, so history is append-only between folds (a sliding window would shift every turn and miss the cache). The fold is one `chat_json` call with 400 tokens out; when the model is down or answers badly the summary is built in code. A backlog (the first fold) folds at most 20 exchanges and skips anything older.
- **"Since we last talked".** Since the principal's previous message (at most 7 days back): runs that ended or merged, approvals that expired, worker questions asked; the newest 8. Owner only.
- **D9.** Facts are files (`~/.resonant/brain/facts/<name>.md`, frontmatter `name`/`description`), at most 50, a 120-char description and 2000 chars of text; `remember`, `forget` (L3, reported `Remembered …` / `Forgot …`) and `list_facts` (L0) are builtins that no intent offers, so the intents path is unchanged. Control and format characters are dropped; the index removes angle brackets. Since the index is in every later prompt, an injected `remember` would persist: L3 stays (the owner's call), the report line shows the whole description, the prompt calls facts context rather than instructions, and BR-1 must route a tainted task's `remember` through D6's ask. The deferred-tool catalog goes through the same cleaning, since extensions write it.

## 3. Out of scope

Group chats; a generic "run any program" tool (programs are extensions); writes by `ask_claude`; replacing qwen; new sandboxes for workers (they stay unguarded).

## 4. Evals and verification

- `evals/task_eval.py` and `evals/task.example.jsonl`: at least 40 real texts across the use cases, each scored on the right tool, a grounded answer (expected facts), no unapproved write when tainted, and latency; run in both modes. `brain.mode: loop` becomes the default when it scores ≥85% graded correct, escalations counted apart.
- Latency: fast path p50 ≤1 s; a simple loop read ~5 s, a three-step task <15 s; "looking into it…" within 2 s of escalating.
- `ScriptedModel` (`e2e/fakes.py`) gains a scripted mode (tool calls and a final reply per test); the label mode stays.
- On the Mini, by text: "where is mycelium", "what's R4 doing", "and where's that?", "what's on my calendar tomorrow", "draft a reply to the last email from X" (draft only), "look up X", a screenshot, "start trade-jev" (asks).

## 6. As built

### BR-1: the brain loop (2026-10-18)

`runners/brain.py` (`BrainRunner`, `runner="brain"`); contracts in [`interfaces.md`](interfaces.md#brain-loop-resonantrunnersbrain-br-1).

- **D1.** `brain.mode: intents | loop` (default `intents`). In `loop` the router skips the labeler: after the fast path, approval replies and the relay's direct step, any free text goes to `relay.free` (as a `question`, so a reply to an open worker question still lands there), else `NewTask(kind="chat", runner="brain", checkpoint={"title": "chat"})`. The brain runner is registered in both modes, so a brain task outlives a switch back.
- **Reuse.** `BrainRunner` subclasses `LocalRunner`: tool calls go through `_call_tool` (registry spec, gate, executor; pinned before a gated call runs or asks), the resume after an approval, the code-built report lines and the resend are the local runner's. `local.py` gained hooks only (`_call_tool(origin=, pin=)`, `_pinned_origin`, a `limit` on `after_effects`/`with_report`, `Answer.meta`); the shared helpers are public now (`Answer`, `CallResult`, `clip_reply`, …). The intents path is unchanged and its tests pass untouched.
- **D4.** Core (17 + `load_tools`): `read_file`, `list_dir`, `search`, `tail_log`, `read_transcript`, `remember`, `forget`, `list_facts`, `ask_claude`, `add_note`, `list_notes`, `add_reminder`, `list_reminders`, `list_runs`, `run_activity`, `start_run`, `system_status`. Everything else the principal may request (builtins, extension chat tools; never job specs, never `mute_extension`, which stays slash-only) is the catalog. `load_tools{names}` is not a registered tool: the loop handles it (never gated or executed), adds up to 8 catalog tools for the rest of the task, and is offered only when the catalog isn't empty. A call to a catalog tool that isn't loaded gets `not loaded: call load_tools with its name first`. A member with `builtin:files` gets the five reads and no catalog.
- **D6.** The task taints once it calls a spec with `untrusted=True` (the read tools, `ask_claude`), any extension or MCP tool, or a builtin that returns text others wrote (`TAINTING_BUILTINS`: `list_runs`, `run_activity`, `answer_worker`, `message_worker`, `recent_logs`, `open_items`, `pulse_preview`, `briefing_preview`: workers read PRs and the web, logs and pulse items quote outside text); every later model-chosen call is `origin="tainted"`. A gated call is pinned with `tainted`, and `_pinned_origin` gates its resume with it, so a tainted `remember` or `add_note` asks before and after the approval (the e2e test checks both audit rows). The intents fallback starts a fresh prompt without the loop's tool results, so it runs untainted.
- **D7.** At most 8 `chat_tools` rounds; a reply with no tool calls is the answer, clipped to 1500. Side effects ≤ 3 and one approval per task, as before; at the cap one `chat_json` narrates and the report lines are always in the reply. 24 tool calls per task in all, as a backstop. The number guard only counts (`number_guard` in `Done.result` and on `runner.brain.answer`), against everything in the prompt and tool results. `On it…` goes out once (dedupe `progress:<task id>`) when a turn passes 6 s; an in-flight progress send finishes before the reply.
- **ask_claude.** When the model calls it and it queued, its `Looking into it…` is the reply and the turn ends (`path: "ask"`); a refusal goes back to the model. **Auto-escalation:** the round cap with no answer, two bad outputs, or the 24-call backstop calls `ask_claude` itself (through the gate and executor) with the message plus `(Resonant's local model ran out of steps; it tried: …)` (`path: "escalate"`). When the principal can't use it or it refuses (daily cap, off, paused): the round cap replies `TOO_MANY_REPLY`, bad output takes the intents path.
- **Fallback.** `ModelUnavailableError`, and bad output that can't escalate, run the intents path for that turn inside the brain runner (the labeler, then `LocalRunner._answer`; `brain_fallback: true` in the result), unless a side effect already ran, in which case its report lines are the reply.
- **D3.** After a brain task's reply is sent, `fold_due` is checked and `fold` runs as a background task (`BrainRunner.idle()` waits for it).
- **Fake.** `ScriptedModel(script=[…])` / `.push(…)`: a list of calls is a round, a string the final reply, an exception is raised; `requests` keeps every prompt and toolset. The label mode is unchanged. `tests/test_e2e_brain.py` covers the briefing answer, multi-step reads, `load_tools`, tainted writes and their resume, `ask_claude` and auto-escalation with the fake claude, the round cap, the fallbacks, members, progress, the prefix hash and the fold.

### BR-7: media, links, watches, proactive (2026-10-18)

Contracts in [`interfaces.md`](interfaces.md#media-links-watches-notices-br-7-docsbrain-planmd-d10-migration-016); phone tests M1–M9 in [`test.md`](test.md); carry-overs in [`followups.md`](followups.md#br-7-carry-overs-media-links-watches-proactive).

- **Attachments.** The chat.db reader reads `attachment` / `message_attachment_join` for the owner's messages only and puts images (JPEG, PNG, GIF, WebP, HEIC), PDFs and voice notes in `payload.attachments` (at most 4, 20 MB each; other types such as link previews and contact cards are counted as skipped). It never opens the files; a chat.db without those tables yields none. An attachment-only message from the owner is now an event (text `""`).
- **Routing.** An owner message with attachments goes to `runner="media"` right after the slash commands, in both modes: no labeler, no brain round. Images and PDFs never touch the local model (qwen3 has no vision).
- **Images and PDFs.** `MediaRunner` (a `LocalRunner`) waits up to 30 s for Messages to finish the download, then runs a code-built `direct_call` of `ask_claude{question: <the text, or "What's in this image?" / "Summarise this PDF briefly.">, kind: "image", attachments}`, so the gate, the executor and the reply (`Looking into it…`) are the slash command path's (origin `explicit`: the owner sent it). The ask runner re-checks each path against BR-5's attachment carve-out and copies it into its folder; a **HEIC** copy is converted there to JPEG with `sips` (`-Z 2048`): Claude takes JPEG, PNG, GIF and WebP only (the vision docs list the four). `sips` missing or failing sends the HEIC as is.
- **Voice.** Checked (the Claude API documents no audio input; Claude Code's Read reads text, images, PDFs and notebooks only), so without `brain.whisper_path` the reply is "I can't play voice notes … Type it instead?". With it, the note is copied into `<RESONANT_HOME>/media/<task>`, converted to a 16 kHz WAV with `afconvert`, run through whisper (whisper.cpp's `whisper-cli` args by default, `brain.whisper_model` as `-m`), and the cleaned transcript is submitted as a new message event (`payload.voice`, dedupe `<message>:voice`) that routes like typed text, except that **it never answers an approval** (approving stays typed). The media task itself sends nothing.
- **Links.** No new router intent: two lines in `BRAIN_SYSTEM` (a mostly-link message or "summarise <url>" → `ask_claude` kind `link` with the whole URL; "watch X, tell me when Y" → load `create_watch`). The prefix hash moved (`025b329b22351d0b`). The e2e test scripts the model's call and checks the hint is in the system prompt; BR-6's evals can score the real model on it.
- **Watches** (migration 016 `brain_watches`, `brain/watches.py`, `tools/watches.py`, `runners/watch.py`). `create_watch` is **L2** (asks with the code-built summary of exactly what will be checked), `list_watches` L0, `cancel_watch` L3; all three are global builtins in the brain's catalog. A watch is either a **tool check** (an L0 read builtin or extension chat tool the principal may use, its args validated against the tool's schema; condition `contains` / `missing` a text, or `changed` against the first check's fingerprint, decided in code: the result never reaches a model) or an **ask check** (a yes/no question; Claude answers YES/NO first). Limits (`brain.watches`): 10 active, every ≥15 minutes (ask checks ≥60, each one an ask against the daily cap), 7 days by default, 30 at most, 3 failed checks in a row end it with a notice. `core/watches` (a `CORE_JOBS` entry, every 5 minutes; paused: skipped) queues a `runner="watch"` task per due watch (compare-and-set on `open_task_id`, so one check at a time). The check runs through `gate.evaluate` with **origin `scheduled`** and the executor; an ask check goes through `AskRunner.enqueue(..., watch=id)`, whose answer reaches `WatchRunner.ask_answered` instead of the owner. A hit is an edge (met now, not at the last check), so a still-true condition never texts twice; with `then: stop` (default) the watch ends `fired`, `then: continue` re-arms.
- **Proactive** (`brain/notices.py`). A brain-authored notice is a pulse item (`core` / `notice/<key>`), sent now unless paused or quiet (held for the hourly pulse), over `extensions.notify.max_per_hour` this hour (held for the pulse), or over **`brain.proactive_per_day`** (default 3) today (held `low`: the briefing). Sends are deduped by key and counted by distinct keys audited `brain.notice` `sent`. Sources today: a watch firing and a watch that stopped failing. The rollup's stalls already ride the hourly pulse and health stays the `HealthMonitor`'s (it texts on degrade and recovery, outside the cap); neither is duplicated.

### BR-5: `ask_claude` and taint (2026-10-18)

- **Taint (D6).** `Origin` gains `"tainted"`; `policy.rule` asks for L2 and L3 when the origin is tainted (L0 allows, L1 asks with a code, a `levels` override to L3 still asks). Standing allows already required `inferred`, so a tainted call never gets one and its prompt offers no `yes always`. The audit row carries the origin. Nothing sets `tainted` yet: BR-1 does, for every model-chosen call after the task read untrusted content (and after `ask_claude`).
- **`ask_claude` (D8)** is `tools/ask.py` (L0, `Effect.READ`: read-only by construction, bounded by the cap; a tainted task may call it) and `runners/ask.py` (`runner="ask"`, task kind `ask`, `uses_claude_slot=False`). Interfaces: [`interfaces.md`](interfaces.md#ask-claude-resonantrunnersask-resonanttoolsask-br-5-docsbrain-planmd-d8). The tool returns `"Looking into it…"` as its text; the loop (BR-1) sends it. The answer goes to the calling task's principal as `Claude: …` and the ask task's result carries `untrusted: true`.
- **Probe (Claude Code 2.1.302, the Mini's login, one run in a scratch dir).** `--restricted`, `--tools`, `--permission-mode dontAsk`, `--allowedTools`/`--disallowedTools`, `--add-dir` and `--no-session-persistence` all exist. With `claude -p --restricted --tools Read,Grep,Glob,WebSearch,WebFetch --permission-mode dontAsk --no-session-persistence --output-format stream-json --verbose`, the `init` event listed exactly `Glob, Grep, Read, WebFetch, WebSearch`, `mcp_servers` was empty and `permissionMode` was `dontAsk`: **claude.ai connectors (Gmail, Calendar) do not load under `--restricted`.** So `email` and `calendar` asks are refused by the init check with `Not done: Calendar isn't reachable from Claude's read-only mode (missing …)`. The allowlist, write-name filter and draft rule are built and tested against fake connector tools, so they work unchanged if a later CLI loads connectors there. Getting email and calendar needs a decision (followups: "ask_claude: email and calendar").
- **Read roots.** One source with the read tools (BR-2): `AskScope.from_settings` takes `brain.read_roots` (or `files.default_roots`), `DEFAULT_READ_DENY` + `brain.read_deny` and Resonant's own secrets; `--add-dir` gets the real top roots and the deny list becomes `Read(...)` rules passed in `--settings`. The ask's cwd moved to `<RESONANT_HOME>/ask` since `runner.work_dir` is always denied.
- **Attachments** (for BR-7): absolute paths under a read root or `brain.ask_claude.attachment_roots` (`~/Library/Messages/Attachments`, carved out of the `~/Library` deny), checked at enqueue and again when copied into the session's empty cwd.
